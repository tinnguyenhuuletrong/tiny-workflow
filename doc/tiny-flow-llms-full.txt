# tiny-workflow Documentation for LLMs

> tiny-workflow is a lightweight, portable workflow engine inspired by Temporal.io. It allows you to write long-running, persistent, and pausable business logic as a single piece of TypeScript code.

This document provides a comprehensive guide for an AI agent coder to understand and use the `tiny-workflow` package.

---

## Overview

**tiny-workflow** is designed to be a simpler, more portable alternative to powerful workflow engines like Temporal. It requires only basic components to run and is built entirely in TypeScript. The core runtime is available via the NPM package `@tiny-json-workflow/runtime-durable-state`.

### Core Principles

- **Code-Driven**: Workflows are defined as TypeScript classes that control the sequence of operations.
- **Separation of Concerns**: The workflow's _control flow_ (the sequence and conditions for steps) is separated from the _business logic_ (the tasks that perform the work).
- **Serializable & Portable**: The entire state of a workflow can be serialized to a single JSON object. This allows you to store the workflow state in any database and resume it later, even on a different machine.
- **Resilient**: Actions within a step are cached using `withAction` to prevent re-execution on resume.

---

## Core Concepts

The entire workflow is built around the `DurableState` class, imported from `@tiny-json-workflow/runtime-durable-state`.

### The `DurableState` Class

This is the foundation of any workflow. You create your own workflow class by extending `DurableState`.

It has three important generic type arguments:

1. `EStep`: A string enum that defines all possible steps in your workflow.
2. `TStateShape`: A TypeScript type that defines the shape of your persistent state (`this.state`).
3. `EAuditLog`: A string union type for custom log messages you want to record.

```typescript
import {
  DurableState,
  type StepIt,
} from "@tiny-json-workflow/runtime-durable-state";

export class YourWorkflow extends DurableState<EStep, TStateShape, any> {
  // ... implementation
}
```

### Steps

Steps are the building blocks of your workflow's logic. Each step is an `async` generator method within your workflow class. The name of the method must correspond to a member of your `EStep` enum. The workflow engine executes these steps in sequence.

A step function's signature looks like this:
`private async *my_step_name(): StepIt<EStep, EStep.next_step_name>`

You return `{ nextStep: EStep.next_step_name }` to transition, or `{ nextStep: null }` to end the workflow.

### State (`this.state`)

The `state` property holds all the data for your workflow that needs to persist across pauses and resumptions. It is a simple JavaScript object that must conform to the `TStateShape` you defined.

### Persistence (Save/Load)

Workflows are designed to be saved and loaded easily.

- `instance.toJSON()`: Serializes the entire workflow instance into a JSON object.
- `YourWorkflowClass.fromJSON(YourWorkflowClass, data)`: A static method to restore a workflow instance from its serialized JSON data.

## Authoring Workflows: The Generated Code Pattern

The recommended way to create a workflow is by using a code generator that scaffolds a workflow file for you. This file separates the workflow's control flow from its implementation.

The generated file has two parts:

1. **GENERATED**: This section contains the `DurableState` class that defines the workflow's structure, steps, and transitions. **You should not edit this part manually.**
2. **IMPLEMENTATION**: This section contains stub functions for the actual business logic (Tasks). **This is where you write your code.**

### The Generated Workflow File Structure

Based on the reference template, a generated workflow file looks like this:

```typescript
// doc/_ref/.generated-workflow.ts

// -----------------
// --- GENERATED ---
// -----------------
import {
  DurableState,
  type StepIt,
} from "@tiny-json-workflow/runtime-durable-state";

// 1. Enums and Types for Steps and State
export enum EStep {
  StartFlow = "StartFlow",
  SendWelcome = "SendWelcome",
  CheckProfile = "CheckProfile",
  SendReminder = "SendReminder",
  EndFlow = "EndFlow",
}

export type TStateShape = {
  userId: string;
  profileIsComplete?: boolean;
};

// 2. A 'Tasks' type defining the business logic functions
export type Tasks = {
  SendWelcome: (context: TStateShape, params: any) => Promise<TStateShape>;
  SendReminder: (context: TStateShape) => Promise<TStateShape>;
};

// 3. The DurableState class defining the control flow
export class UserOnboardingFlow extends DurableState<EStep, TStateShape, any> {
  constructor(private tasks: Tasks) {
    super(EStep.StartFlow);

    // collect and resgister all step handler
    Object.values(EStep).map((step) =>
      this.stepHandler.set(step, this[step].bind(this))
    );
  }

  // 4. Step methods that call tasks via withAction
  private async *SendWelcome(): StepIt<EStep, EStep.CheckProfile> {
    const res = await this.withAction<TStateShape>("SendWelcome", async () => {
      // Delegates to the injected task implementation
      return this.tasks.SendWelcome(this.state, undefined);
    });

    if (res.it) yield res.it;
    if (res.value) this.state = res.value; // Update state with the task's result
    return { nextStep: EStep.CheckProfile };
  }

  private async *CheckProfile(): StepIt<EStep, any> {
    if (this.state.profileIsComplete == true) {
      return { nextStep: EStep.EndFlow };
    }
    if (this.state.profileIsComplete == false) {
      return { nextStep: EStep.SendReminder };
    }
    return { nextStep: null }; // Default fall-through
  }

  // ... other steps ...
}

// --- IMPLEMENTATION ---

// 5. Your part: Implement the task functions
async function SendWelcome(
  context: TStateShape,
  params: any
): Promise<TStateShape> {
  console.log(`Sending welcome email to user ${context.userId}...`);
  // TODO: Implement task 'Send Welcome Email'
  return context; // Return the new state
}

async function SendReminder(context: TStateShape): Promise<TStateShape> {
  console.log(`Sending profile reminder to user ${context.userId}...`);
  // TODO: Implement task 'Send Profile Reminder'
  return context;
}

// 6. A factory to wire it all together
export function createWorkflow() {
  return new UserOnboardingFlow({
    SendWelcome,
    SendReminder,
  });
}
```

### The Task-Oriented Pattern

This pattern separates the _what_ from the _how_.

- The **`UserOnboardingFlow` class** defines _what_ steps exist and in _what order_ they run. It handles the workflow's persistence and resilience.
- The **`SendWelcome` and `SendReminder` functions** define _how_ a specific piece of business logic is executed (e.g., calling an API, sending an email).

Your main job as a developer is to fill in the `// TODO:` sections within the implementation functions.

The step methods in the generated class use `withAction` to call your task implementations. This is crucial because it ensures that even if the workflow is paused and resumed, your business logic (like sending an email) is **executed only once**.

## Key API Methods

(These methods are used inside the `DurableState` class and are typically part of the generated code.)

### `withAction<T>(key, action)`

Executes and caches a function. In the generated pattern, this is used to call your task implementations. The `action`'s return value should be the new state object, which then updates `this.state`.

```typescript
// Inside a generated step method:
const res = await this.withAction<TStateShape>("SendWelcome", async () => {
  return this.tasks.SendWelcome(this.state, undefined);
});

if (res.it) yield res.it;
if (res.value) this.state = res.value; // Update the workflow's state
```

### `waitForMs(key, duration)`

Pauses the workflow for a specified duration. Useful for scheduled reminders or delays.

```typescript
// Inside a step method:
const wait = this.waitForMs("wait_a_day", 24 * 60 * 60 * 1000);
if (wait.it) yield wait.it;
// This code runs after the delay
```

### `waitForEvent<T>(key, requestPayload)`

Pauses the workflow to wait for external data, such as user input.

```typescript
// Inside a step method for an interactive workflow:
const { it, value } = this.waitForEvent<number>("get_user_guess", {
  question: "Guess a number between 1 and 100",
});
if (it) yield it;

const userGuess = value(); // The value provided by resolveResume()
```

## Advanced Topics

The following concepts from the original library structure are still relevant for managing and running the generated workflows.

### Advanced Pattern: Managing DAGs and Long-Running Tasks

For complex workflows, you may need to manage multiple long-running tasks that can execute in parallel, sometimes with dependencies (forming a Directed Acyclic Graph, or DAG). A simple `withAction` is not ideal for tasks that take a long time to complete, as you might want to check their status periodically without blocking the entire workflow engine.

The recommended approach is the **"Start and Poll"** pattern. This separates the initiation of a task from checking its completion status.

- **`doStart`**: A non-blocking function that triggers an external task (e.g., calls an API to start a batch job). The workflow records that the task is now "processing".
- **`pollStatus`**: A function that checks if the task is done. The workflow calls this periodically until the task completes.

This pattern makes the workflow highly resilient and resumable. The status of all tasks is stored in the workflow's state, so it can be saved, loaded, and resumed at any point, and the polling will continue where it left off.

#### Example: A DAG Task Engine

Let's look at an implementation of this pattern, based on `examples/flows/dagTask.ts`. This example can manage multiple parallel sequences of tasks.

**1. State and Handler Definition**

First, define the shape of your tasks and a handler interface for the business logic.

```typescript
// The information for a single task
export type TaskInfo<T = Record<string, any>, IDType = string> = {
  id: IDType;
  status?: "waiting" | "processing" | "end";
  ctx?: T;
};

// A sequence of tasks that run one after another
export type TaskSequence<T = any, IDType = string> = TaskInfo<T, IDType>[];

// The main state contains multiple sequences that can run in parallel
export type TStateShape = Partial<{
  sequences: TaskSequence[];
}>;

// The handler interface for starting and polling tasks
export type TaskDagHandler<D = any, K = string> = {
  doStart: (itm: TaskInfo<D, K>) => Promise<void>;
  pollStatus: (itm: TaskInfo<D, K>) => Promise<TaskInfo["status"]>;
};
```

**2. The Workflow Engine (`DagTaskEngine`)**

The workflow class orchestrates the process. The core logic resides in a processing step that loops until all tasks are done.

```typescript
class DagTaskEngine extends DurableState<EStep, TStateShape, any> {
  constructor(private logicHandler: TaskDagHandler) {
    // ... constructor setup ...
  }

  // The main processing step
  private async *step_process(): StepIt<EStep, any> {
    // Get all task chains to process in parallel
    const tasks = (this.state.sequences ?? []).map((chain) =>
      this._processOneChain(chain)
    );

    // Loop and poll until all tasks in all chains are 'end'
    while (!this.allDone) {
      // Advance each chain's logic by one step
      await Promise.allSettled(tasks.map((itm) => itm.next()));

      // Yield control to pause the workflow.
      // The runtime will resume it later for the next polling cycle.
      yield {
        canContinue: false,
        activeStep: EStep.step_process,
      };
    }

    return { nextStep: EStep.step_end };
  }

  // Processes a single chain of dependent tasks
  private async *_processOneChain(chain: TaskInfo[]) {
    for (let i = 0; i < chain.length; i++) {
      const itm = chain[i];
      if (itm.status === "end") continue; // Already done

      // If task is new, start it
      if (itm.status === "waiting" || itm.status === undefined) {
        await this.logicHandler.doStart(itm);
        itm.status = "processing";
        // ... (update state and logs)
      }

      // If task is running, poll its status
      if (itm.status === "processing") {
        const nextStatus = await this.logicHandler.pollStatus(itm);
        itm.status = nextStatus;
        if (nextStatus === "end") {
          // ... (update state and logs)
          continue; // Move to next task in the chain
        }
      }

      // Yield, and on next resume, re-evaluate the *same* task
      yield;
      i--;
    }
  }

  public get allDone() {
    return (this.state.sequences ?? []).every((chain) =>
      chain.every((itm) => itm.status === "end")
    );
  }

  // ... other methods ...
}
```

**3. Resumability in Action**

The `main` function in the example demonstrates saving and loading.

1.  An instance of `DagTaskEngine` is created and run for a few iterations.
2.  The workflow is paused, and its state is serialized to a JSON object using `ins.toJSON()`.
3.  Later, a new instance is created from this JSON data using `DagTaskEngine.fromJSON(DagTaskEngine, data)`.
4.  The new instance is provided with the `logicHandler` and execution is resumed. The workflow seamlessly continues polling the tasks based on the restored state.

This pattern is extremely powerful for orchestrating complex, long-running, and distributed processes in a fault-tolerant way.

### Advanced Pattern: Interacting with Running Workflows

Workflows often need to be queried or updated by external systems or user actions while they are running (or paused). The `tiny-workflow` runtime supports this through a pattern that separates the workflow "server" (the process) from the "client" (the interactor).

- **Workflow as a "Server"**: The workflow instance runs in the background, managed by the `WorkflowRuntime`. It executes the long-running business logic, pausing for timers (`waitForMs`) or waiting for events (`waitForEvent`).
- **External Code as a "Client"**: A separate part of your application acts as a client. It can read the workflow's state or send signals/data to it without interrupting its execution loop directly.

This is demonstrated in `examples/flows/intervalPayment.ts`, which implements a recurring subscription service.

#### Example: Interval Payment Subscription

**1. Defining "Action" Methods**

The client interacts with the workflow by calling public methods that modify the state. These are not step handlers. They are designed to be called from outside the workflow's own execution loop.

```typescript
class IntervalPaymentFlow extends DurableState<EStep, TStateShape, EAuditLog> {
  // ...

  // An "action" method to add usage data to the current state.
  actionAddUsage(usageItem: UsageItem) {
    if (this.state.status != "active")
      throw new Error("status is not active. can not process");

    this.state.currentUsages.push({ ...usageItem });
    this.addLog({ type: "add_usage", values: { ...usageItem } });
  }

  // An "action" method to change the workflow's status.
  actionCancel() {
    if (this.state.status != "active")
      throw new Error("status is not active. can not process");

    this.state.status = "cancel";
    this.addLog({ type: "cancel", values: {} });
  }

  // ... step handlers like step_wait, step_send_receipt ...
}
```

**2. Separating the Runner and the Client**

The `main` function in the example starts two concurrent tasks:

- `runBackground`: This function is the "server". It calls `runtime.run(ins, runId)` to start the workflow and lets it run its course, handling timers and step transitions.
- `runFrontend`: This function is the "client". It provides a command-line interface for a user to interact with the running workflow.

```typescript
// In main():
// "Server" task
await ctx.runner.addTask(runBackground(runId, ctx, ins));

// "Client" task
ctx.runner.addTask(runFrontend(runId, ctx));

// ---

async function runBackground(runId, ctx, ins) {
  // Executes the workflow logic
  let result = await ctx.runtime.run(ins, runId);
  // Schedules the next run if the workflow is paused on a timer
  ctx.runner.addTask(ctx.scheduleNextRun(runId, result));
}
```

**3. Interacting from the Client**

The "client" (`runFrontend`) can safely read and modify the workflow's state.

```typescript
async function runFrontend(runId, ctx) {
  // Listen for user commands (e.g., from a CLI or an HTTP request)
  for await (const line of console) {
    const cmd = line.trim();

    if (cmd === "/add") {
      // Use a transaction to ensure atomic state updates
      ctx.withTransaction(runId, async () => {
        // 1. Load the latest version of the workflow instance
        const ins = await ctx.runtime.createInstanceByRunId(
          runId,
          IntervalPaymentFlow
        );

        // 2. Call the public action method
        ins.actionAddUsage({ item: "new_item", amount: 10 });
        console.log(`add usage`);

        // 3. The context will automatically save the updated state when the transaction completes
      });
    } else if (cmd === "/cancel") {
      ctx.withTransaction(runId, async () => {
        const ins = await ctx.runtime.createInstanceByRunId(
          runId,
          IntervalPaymentFlow
        );
        ins.actionCancel(); // This changes state.status to "cancel"
        console.log("canceled");
      });
    }
  }
}
```

When the user types `/cancel`, `actionCancel()` is called. It changes `state.status` to `"cancel"`. The next time the workflow's `step_wait` resumes (e.g., after its `waitForMs` timer fires), the `while (this.state.status === "active")` loop condition will be false, and the workflow will naturally proceed to the cancellation or end steps.

This client-server pattern is ideal for interactive applications, such as subscription management, processes requiring manual approval, or any workflow that needs to react to external input on its own time.

### Managing Multiple Workflows

For real-world applications, you'll need to manage many workflow instances concurrently. The `WorkflowRuntime` and a `Context` object are used for this. These would be imported from `@tiny-json-workflow/runtime-durable-state`.

- **`WorkflowRuntime`**: A helper class that orchestrates running, pausing, and resuming workflows.
- **`SimpleContext`**: A basic in-memory context for storing workflow state and managing locks. You would extend this to connect to a real database.

### Example Runtime Usage

```typescript
// This code would consume the generated 'createWorkflow' factory
import {
  SimpleContext,
  WorkflowRuntime,
} from "@tiny-json-workflow/runtime-durable-state";
import { createWorkflow, UserOnboardingFlow } from "./.generated-workflow"; // Your generated file

async function main() {
  const ctx = new SimpleContext();
  const runtime = new WorkflowRuntime({
    ctx,
    genRunId: async () => `user-onboarding-${Date.now()}`,
    InstanceClass: UserOnboardingFlow, // Pass the class constructor
  });

  const onboardingFlow = createWorkflow();
  // Set initial state if needed
  onboardingFlow.setState({ userId: "user-123", profileIsComplete: false });

  // Run the workflow
  let result = await runtime.run(onboardingFlow);

  switch (result.status) {
    case "need_resume":
      {
        // check more info in result.resumeEntry. Which contain the type and resume token
        // If the workflow is waiting for a timer, the context can schedule it
        if (result.resumeEntry.type == "timer")
          await ctx.scheduleNextRun(result.runId, result);
      }
      break;
    case "error":
      // TODO: Throw of report error in result.error
      break;
    case "finished":
      // Workflow done
      break;
  }

  // ... wait for all workflows to finish
  await ctx.runner.idle();

  // Bonus: Get data by RunId
  const runData = await ctx.load(result.runId);
}
```

### Examples examples/flows/dagTask.ts

```ts
import {
  DurableState,
  type StepIt,
} from "@tiny-json-workflow/runtime-durable-state";
import { setTimeout } from "node:timers/promises";
import assert from "node:assert";

enum EStep {
  step_begin = "step_begin",
  step_process = "step_process",
  step_end = "step_end",
}

export type TaskInfo<T = Record<string, any>, IDType = string> = {
  id: IDType;
  status?: "waiting" | "processing" | "end";
  ctx?: T;
};

export type TaskSequence<T = any, IDType = string> = TaskInfo<T, IDType>[];

export type TStateShape = Partial<{
  sequences: TaskSequence[];
}>;

// additional audit log message
type EAuditLog = "start_hit" | "end_hit";

export type TaskDagHandler<D = any, K = string> = {
  doStart: (itm: TaskInfo<D, K>) => Promise<void>;
  pollStatus: (itm: TaskInfo<D, K>) => Promise<TaskInfo["status"]>;
};

class DagTaskEngine extends DurableState<EStep, TStateShape, EAuditLog> {
  constructor(private logicHandler: TaskDagHandler) {
    super(EStep.step_begin, {
      withAuditLog: false,
      debug: false,
    });

    // collect and resgister all step handler
    Object.values(EStep).map((step) =>
      this.stepHandler.set(step, this[step].bind(this))
    );
  }

  updateLogicHandler(logicHandler: TaskDagHandler) {
    this.logicHandler = logicHandler;
  }

  setState(state: TStateShape) {
    this.state = state;
  }

  override exec(runId?: string) {
    if (!this.logicHandler) throw new Error("missing logicHandler");

    return super.exec();
  }

  private async *step_begin(): StepIt<EStep, EStep.step_process> {
    return { nextStep: EStep.step_process };
  }

  private async *step_process(): StepIt<
    EStep,
    EStep.step_end | EStep.step_process
  > {
    const sequences = this.state.sequences ?? [];

    const tasks = sequences.map((chain) => this._processOneChain(chain));

    while (!this.allDone) {
      const res = await Promise.allSettled(tasks.map((itm) => itm.next()));
      const errors = res.filter((itm) => itm.status === "rejected");
      if (errors.length !== 0) {
        throw new Error(
          `Got errors: ${JSON.stringify(
            errors.map((err) => {
              return {
                message: err?.reason?.message,
                stackTrace: err?.reason?.stack,
              };
            })
          )}`
        );
      }

      yield {
        canContinue: false,
        activeStep: EStep.step_process,
      };
    }

    return { nextStep: EStep.step_end };
  }

  private async *step_end(): StepIt<EStep, null> {
    return { nextStep: null };
  }

  private async *_processOneChain(chain: TaskInfo[]) {
    for (let i = 0; i < chain.length; i++) {
      const itm = chain[i];
      if (itm.status === "end") continue;

      const isWaiting = itm.status === "waiting" || itm.status === undefined;
      if (isWaiting) {
        await this.logicHandler.doStart(itm);
        itm.status = "processing";
        itm.ctx = itm.ctx || {};
        itm.ctx.startTime = Date.now();
        this.addLog({
          type: "start_hit",
          values: {
            id: itm.id,
          },
        });
      }

      // poll
      if (itm.status === "processing") {
        const nextStatus = await this.logicHandler.pollStatus(itm);
        itm.status = nextStatus;
        if (nextStatus === "end") {
          itm.ctx = itm.ctx || {};
          itm.ctx.endTime = Date.now();
          this.addLog({
            type: "end_hit",
            values: {
              id: itm.id,
            },
          });
          continue;
        }
      }

      yield;
      i--;
    }
  }

  public get allDone() {
    const sequences = this.state.sequences ?? [];
    return sequences.every(this.isOneChainDone);
  }

  private isOneChainDone(chain: TaskInfo[]) {
    return chain.every((itm) => itm.status === "end");
  }
}

//------------------------------
//  Helper

function buildSequence<T = any, K = string>() {
  const sequence: TaskSequence<T, K> = [];
  const ins = {
    build() {
      return sequence;
    },
    isEmpty() {
      return sequence.length === 0;
    },
    next(taskInfo: TaskInfo<T, K>) {
      sequence.push(taskInfo);
      return ins;
    },
  };
  return ins;
}
```

```ts
import {
  DurableState,
  SimpleContext,
  WorkflowRuntime,
  type StepHandler,
  type StepIt,
  type WorkflowRuntimeOpt,
} from "@tiny-json-workflow/runtime-durable-state";

enum EStep {
  step_begin = "step_begin",
  step_wait = "step_wait",
  step_send_receipt = "step_send_receipt",
  step_cancel = "step_cancel",
  step_end = "step_end",
}

type UsageItem = {
  item: string;
  amount: number;
};
type ReceiptItem = {
  cycle: number;
  createdAt: number;
  usages: UsageItem[];
  deliveryId?: string;
};
type TStateShape = {
  userEmail: string;
  paymentIntervalMs: number;

  _cycle: number;
  _nextPaymentAt: number;

  status: "active" | "cancel";
  currentUsages: UsageItem[];

  receipts: Array<ReceiptItem>;
};
type EAuditLog = "set_param" | "add_usage" | "bill_sent" | "cancel";

class IntervalPaymentFlow extends DurableState<EStep, TStateShape, EAuditLog> {
  // Type Safeguard & Auto register
  private _static(key: EStep): StepHandler<EStep> {
    return this[key];
  }
  private _collectAndRegisterSteps() {
    Object.values(EStep).map((step) =>
      this.stepHandler.set(step, this._static(step).bind(this))
    );
  }
  constructor() {
    super(EStep.step_begin, {
      withAuditLog: false,
      debug: true,
    });
    this._collectAndRegisterSteps();
  }

  setParam(tmp: Pick<TStateShape, "userEmail" | "paymentIntervalMs">) {
    this.state = { ...this.state, ...tmp };
    this.addLog({
      type: "set_param",
      values: {
        ...tmp,
      },
    });
  }

  actionAddUsage(usageItem: UsageItem) {
    if (this.state.status != "active")
      throw new Error("status is not active. can not process");

    this.state.currentUsages.push({ ...usageItem });
    this.addLog({
      type: "add_usage",
      values: {
        ...usageItem,
      },
    });
  }

  actionCancel() {
    if (this.state.status != "active")
      throw new Error("status is not active. can not process");

    this.state.status = "cancel";

    this.addLog({
      type: "cancel",
      values: {},
    });
  }

  private async *step_begin(): StepIt<EStep, EStep.step_wait> {
    this.state = {
      ...this.state,
      ...{
        status: "active",
        _cycle: 0,
        _nextPaymentAt: Date.now() + this.state.paymentIntervalMs,
        currentUsages: [],
        receipts: [],
      },
    };
    return { nextStep: EStep.step_wait };
  }

  private async *step_wait(): StepIt<
    EStep,
    EStep.step_cancel | EStep.step_send_receipt
  > {
    while (this.state.status === "active") {
      const cycle_no = this.state._cycle;
      const needToWaitMs = this.state._nextPaymentAt - Date.now();
      const res = this.waitForMs(
        `wait_for_end_cycle_${cycle_no}`,
        needToWaitMs
      );
      if (res.it) {
        this._debug("wait for cycle_no=", cycle_no);
        yield res.it;
      }

      if (this.state.status !== "active") {
        return { nextStep: EStep.step_cancel };
      }

      this.state._cycle = this.state._cycle + 1;
      this.state._nextPaymentAt = Date.now() + this.state.paymentIntervalMs;
      this._debug(
        "inc cycle_no=",
        this.state._cycle,
        "nextCheck=",
        this.state._nextPaymentAt
      );

      // have any usage
      if (this.state.currentUsages.length > 0) {
        const receipt: ReceiptItem = {
          cycle: cycle_no,
          createdAt: Date.now(),
          usages: [...this.state.currentUsages],
        };
        this.state.receipts.push(receipt);
        this.state.currentUsages = [];

        return { nextStep: EStep.step_send_receipt };
      }
    }

    return { nextStep: EStep.step_cancel };
  }

  private async *step_send_receipt(): StepIt<
    EStep,
    EStep.step_wait | EStep.step_end
  > {
    const lastReceipt = this.state.receipts.at(-1);
    const cycle_no = lastReceipt?.cycle;
    if (!lastReceipt) throw new Error("lastReceipt is null");

    const res = await this.withAction<string>(
      `send_receipt_email_${cycle_no}`,
      async () => {
        const deliveryId = Date.now().toString(32);
        this._debug(
          `Send bill for cycle_no=${cycle_no} to email=${
            this.state.userEmail
          }, receipt=${JSON.stringify(lastReceipt)}`
        );

        this.addLog({
          type: "bill_sent",
          values: {
            receipt: { ...lastReceipt },
          },
        });
        return deliveryId;
      }
    );

    if (res.it) {
      yield res.it;
    }
    if (res.value) lastReceipt.deliveryId = res.value;

    if (this.state.status === "active") return { nextStep: EStep.step_wait };
    else return { nextStep: EStep.step_end };
  }

  private async *step_cancel(): StepIt<
    EStep,
    EStep.step_end | EStep.step_send_receipt
  > {
    const cycle_no = this.state._cycle;

    // any usage ?
    if (this.state.currentUsages.length > 0) {
      const receipt: ReceiptItem = {
        cycle: cycle_no,
        createdAt: Date.now(),
        usages: [...this.state.currentUsages],
      };
      this.state.receipts.push(receipt);
      this.state.currentUsages = [];

      return { nextStep: EStep.step_send_receipt };
    }

    return { nextStep: EStep.step_end };
  }

  private async *step_end(): StepIt<EStep, null> {
    return { nextStep: null };
  }
}

async function runFrontend(
  runId: string,
  ctx: MemContext<IntervalPaymentFlow>
) {
  const usage = `
  /state:         print state as json
  /add [num]:     add a random usage. default num=1
  /save:          save storage to file
  /cancel:        cancel
  /exit:          exit
  `;
  console.log(`🤟 Wellcome ${"info@company.com"} to IntervalPayment 🤟`);
  console.log(usage);

  type cmdType = "/state" | "/add" | "/save" | "/exit" | "/cancel";

  for await (const line of console) {
    const tmp = line.trim().split(" ");
    const cmd = tmp[0] as cmdType;
    const args = tmp.slice(1);

    switch (cmd) {
      case "/state":
        {
          const ins = await ctx.runtime.createInstanceByRunId(
            runId,
            IntervalPaymentFlow
          );
          console.log({
            step: ins.currentStep,
            state: ins.currentState,
            runtimeUsage: ctx.runner.stats(),
          });
        }
        continue;
      case "/add": {
        {
          const sample = parseInt(args[0] ?? "1");

          ctx.withTransaction(runId, async () => {
            const ins = await ctx.runtime.createInstanceByRunId(
              runId,
              IntervalPaymentFlow
            );
            for (let i = 0; i < sample; i++) {
              const item = `id_${Math.round(Math.random() * 100)}`;
              const amount = Math.round(Math.random() * 10);
              ins.actionAddUsage({
                item,
                amount,
              });
              console.log(`add usage ${item} - ${amount}`);
            }
          });
        }
        continue;
      }

      case "/save":
        {
          ctx.syncDBToFile();
          console.log("saved");
        }
        continue;

      case "/cancel":
        {
          ctx.withTransaction(runId, async () => {
            const ins = await ctx.runtime.createInstanceByRunId(
              runId,
              IntervalPaymentFlow
            );
            ins.actionCancel();
            console.log("canceled");
          });
        }
        return;

      case "/exit":
        console.log("exit!");
        process.exit(0);

      default:
        console.log(usage);
    }
  }
}
```
